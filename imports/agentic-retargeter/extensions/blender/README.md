# G1 Retargeting Refinement for Blender

An offline English sidebar for native robot joint editing, local-window repair, approach/closure timing, Blender interpolation, native candidate export and hand/contact inspection. Version 0.10.0 targets Blender 4.2–4.3 and is tested with **Blender 4.3.2**. The 4.4+ layered animation API is not supported by this version.

## Build and install

From this repository, using Python 3.11+:

```bash
python extensions/blender/build.py --out dist/blender-v001
```

In Blender, open **Edit → Preferences → Get Extensions → menu → Install from Disk**, select `grail_g1_retargeting-0.10.0.zip` and enable it. Open the 3D View or Graph Editor sidebar with **N → GRAIL G1**. No pip installation is needed inside Blender. Original models and case data are supplied separately. Optional Newton queries and local repair use separately configured Python runtimes. Persistent canonical hands and per-frame Newton/contact-map caches support full-sequence playback, alongside refresh on paused edits; see [collision configuration and controls](../../docs/collision.md).

The builder bundles the current repository kit, records source/packaged SHA256 hashes and its import adapter, and includes the original LICENSE. It needs no GRAIL checkout, artifact scripts or model downloads. Do not maintain hand-edited kit copies under the extension source; the build output is generated.

## Edit and review

1. Select the native robot NPZ and its compiled model snapshot. Initial conversion from human motion remains in the external GMR pipeline; see the repository's upstream handoff guide.
2. For geometry preview, open the matching portable G1 `.blend`. An empty or unrelated scene supports **curve controls only**; the extension does not import arbitrary robot rigs.
3. Load actual model joints. Explicitly enable permitted limited hinges; none are selected by default. Choose a source-frame window, closure onset/completion, native values and optional protected milestones, or load an existing curve plan.
4. Create controls and edit channels in the Graph Editor. Source frame **0 = Blender frame 1**. Default interpolation is **Bézier / Auto Clamped**, with handle smoothing **None**. Continuous Acceleration is optional and must be evaluated on exported motion.
5. Exact mesh preview requires the matching portable scene and the explicit **Enable Exact Preview** action, which executes that trusted scene's preview code. It does not run at installation or file open.
6. Save/export into a new directory. The exporter checks original joint limits, declared endpoints, protected milestones, frozen coordinates and fractional curve samples. Outputs include a native candidate, curves, comparison report and editable `.blend`. Continue subsequent edits from that chosen `.blend`, saving a new version for each round so accumulated changes remain available. Saving changes the current document's save path.
7. Review intended thumb/long-finger roles, auxiliary-digit clearance, matching-time material contact, complete original meshes, source/depth alignment and temporal behavior. If the requested defect remains, revise the contact definition, mounted palm pose or path keys and repeat. A smoother curve or solver cap does not complete a contact correction.

Every export is **UNREVIEWED**. Separate manual review records bind the actual candidate hash. Original model/data inputs and previous checkpoints are preserved. Saved export/preview Text buttons require the matching installed extension and call the same guarded operators; scene or bundled-code mismatches are rejected. Reopening and exporting curves does not require enabling mesh preview.

## Inspect hands and contacts

Load a scene-specific inspection JSON in **N → GRAIL G1 → Hand & Contact Dashboard**, then click **Open Inspection Dashboard**. One native Blender viewport compares all hands and the object across **Measured**, **Predicted / authored** and **Difference** rows. **Return to Editing View** restores local navigation. Optional **Follow timeline (on pause)** refreshes after scrubbing or pose changes settle, using already enabled native preview. Select **Individual views** for the earlier camera-by-camera layout. Diagnostic copies show the current finger pose in wrist coordinates, digit labels and contact heatmaps without changing source geometry or materials. Export a JSON report to retain exact mesh identities and measurements. Refresh after edits or frame changes: the views are labeled snapshots.

The [hand inspection guide](../../docs/hand-inspection.md) describes object/hand bindings and the per-vertex prediction schema. Predicted maps are imported, not generated by a bundled predictor. Model predictions, authored hypotheses and unavailable coverage retain distinct labels. Measured maps are unsigned surface proximity, not physical contact or signed penetration.

Optional contact-pose fitting remains in `tools/contact_edit/pose.py`, in its documented Python environment. The extension does not bundle SciPy, MuJoCo, inference models or motion libraries and does not establish contact, collision clearance or physical validity.

## Newton collision diagnostics

Use **N → GRAIL G1 → Newton Collision Diagnostics** to query explicit original-mesh pairs through the pinned external `ho_contact` / Newton runtime, then inspect paired contact points and segments in the mounted scene. The [collision guide](../../docs/collision.md) covers runtime setup, configuration, offline queries and evidence export. Geometry/frame/native-control changes invalidate old snapshots. The backend detects contact candidates; it does not repair motion, and its unsigned point distances are not penetration depths.

## Local window repair

**N → GRAIL G1 → Local Window Repair** uses the shared [audit and repair tools](../../tools/repair/README.md) from the same extension. Set a repair-template JSON, an external Python executable with NumPy/SciPy/MuJoCo, and a writable output root. The template binds the original robot XML, object mesh, material contact descriptors, collision pairs, native correction bounds and optional source/temporal gates. It is specific to the current robot and object; loading a motion does not invent these constraints.

1. Load the template and choose the inclusive source-frame window, permitted joints and protected frames. Source frame **0 = Blender frame 1**. Window endpoints and protected poses stay fixed.
2. Click **Run Local Repair**. The extension snapshots the current native curve values and submits a versioned request to its bundled worker through the configured external Python. Work runs outside Blender's UI process. No repair starts merely by installing the extension or opening a file.
3. Read the audit status and click **Preview Candidate** to inspect the candidate with the existing mounted and canonical contact views. A second worker audits the actual Blender subframe poses after curve quantization. Existing contact evidence becomes stale when the pose changes; configured automatic Newton refresh updates it, or refresh diagnostics manually. A rejected candidate can be inspected, but retains its rejection and inherited-failure reports.
4. **Restore Original** returns to the saved pre-preview Action; **Apply to Editable Curves** retains the candidate as an explicit unreviewed edit after its preview audit. Both Actions remain available. Neither operation selects or accepts the motion. Save/export to a new path and perform the normal native round-trip and motion review.

The first UI version requires native **LINEAR replay** for the submitted motion. The solver audits interpolation between native samples; arbitrary Bézier curves may follow different paths between those samples and are not silently converted. Existing scene edits are sampled for the request, and the original `.blend` is not overwritten by running or previewing a repair. Changes made while a worker runs invalidate applying its result to that changed state.

For compatible older scenes, **Update Compatible Scene Bindings** updates the
exact known metadata-only exporter changes while preserving motion and curves. It
rejects unrelated embedded-code changes and does not execute those scripts.
When reopening a file saved during an unmodified transient preview, the add-on
restores the original Action without starting a worker. If those saved Actions
were edited, it preserves both and asks for manual review instead of overwriting
them. Applied edits remain applied after reopening.

The extension packages the bridge, worker and shared repair implementation with source hashes, while MuJoCo and SciPy remain in the external runtime. Select **Native CPU** for the existing coupled solver or **Material GPU (experimental)** with an explicit `cuda:N` device and external Torch/Warp runtime. The GPU method keeps fixed material contacts and performs the same independent original-triangle audit; it is not a Newton dynamics simulation. Backend and device changes invalidate stale jobs. Newton diagnostics and repair share review views while retaining their separate runtime and evidence bindings. Solver completion or `affected_scope_passed` does not turn an overall `REJECTED_BY_AUDIT` candidate into a reviewed motion.

Use separate external environments for material repair (validated Warp 1.12.1)
and pinned Newton diagnostics (Warp 1.9.1). Configure their respective Python
fields; upgrading Warp in the diagnostics environment would invalidate its pin.

The repair template can independently select compiled CPU audits with
`"audit": {"geometry_backend": "numba", "device": "cpu", ...}`. Install the
optional `compiled-audit` extra in **Solver Python** for this path; Numba/LLVM
remain outside Blender. It uses the same original triangle checks and works
with either proposal backend. Changing the template invalidates stale jobs.

An optional [iteration seed](../../tools/repair/README.md#continue-from-a-selected-smoother-seed)
keeps a selected smoother motion separate from the original parent. Load the
bound seed into native curves before running its template. The panel shows the
seed and smoothness status; the original correction bounds and contacts stay
fixed. A strict smoothness failure blocks Apply, while Preview and Restore
remain available for diagnosis. Checks include actual wrist orientation and
integer derivative stencils across joins; they do not certify continuous-time
jerk between LINEAR keys.

## Automation / Blender MCP

The host assistant can use an installed Blender MCP connection when available, or foreground `blender -b --python` execution. This extension does not bundle an MCP client and makes no model API calls. The repository's [`blender-edit` command](../../docs/blender-agent.md) runs one bounded local round, saves a new `.blend` and native export, and renders inspection evidence.

After enabling the extension, use its operators inside Blender through either transport:

```python
import bpy
s = bpy.context.scene.grail_g1
s.native_path = "/case/robot_native.npz"
s.model_path = "/case/compiled_model.npz"
s.plan_path = "/case/curve_plan.json"
s.output_dir = "/case/new_curve_candidate"
assert bpy.ops.grail_g1.validate_inputs() == {"FINISHED"}
assert bpy.ops.grail_g1.create_controls() == {"FINISHED"}
# Optional for a trusted, compatible portable scene only:
# bpy.ops.grail_g1.enable_preview(confirmed=True)
# Edit native joint curves and inspect the result before exporting.
assert bpy.ops.grail_g1.export_native() == {"FINISHED"}
```

Treat the saved `.blend` as the editable state across rounds. Preserve its native curves and original model/object bindings, refresh the hand/contact dashboard after edits, and verify exported geometry after reopening. Keep prior scene versions and their evidence; a successful operator is not motion acceptance.

## Isolated installation

Install the generated ZIP into an isolated Blender profile before use; the extension checks import isolation, scene preservation, native curve editing, frozen fields, protected endpoints, export and reopen equality. These tooling checks do not accept any real robot motion.
